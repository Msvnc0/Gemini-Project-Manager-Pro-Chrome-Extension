- Undo button: Optional "undo" action parameter

**Existing call sites to update:**

- `project-tree.js` — 3 additional showToast calls (search for `showToast(`)

**Note:** Module also exports `showToast` for ES module import in new code. Both global and import paths work.

### 1.2 Missing Modal Implementations

**`showBulkMoveModal()`:** Modal for moving selected chats to target project/folder. Uses existing `createModal` pattern from `ui_elements.js`. Wraps existing `gpmBulkMoveToProject()` (project-tree.js:1095) with a project/folder picker UI instead of sequential prompting.

**`showBulkTagModal()`:** Modal for bulk tag assignment/removal on selected chats. Wraps existing `gpmBulkAssignTags()` (project-tree.js:1102) with a tag picker UI.

**`showCreateTagModal()`:** Full implementation replacing empty stub in `tag-ui.js`. Form with name, color picker, optional parent tag selection.

### 1.3 Tag Schema Unification

**Problem:** Two conflicting tag schemas exist:
- `GPMStorage` (storage.js): `{ [tagId]: { id, name, color, count, createdAt, updatedAt } }`
- `GPMTagsManager` (tags-manager.js): `[{ id, name, nameEn, color, icon }]`
- `GPMStorage.assignTagsToChat()` has a hardcoded **5-tag limit** — auto-tagger (4.1) must respect this

**Solution:** Standardize on a single canonical tag schema in `GPMStorage`:
```js
{ [tagId]: { id, name, color, icon, count, parentId, createdAt, updatedAt } }
```

**Field mapping during migration:**
- `GPMTagsManager.nameEn` → `name` (based on current locale, fallback to `nameEn`)
- `GPMTagsManager.icon` → preserved as `icon`
- `GPMStorage.count` → preserved
- New field: `parentId` (for hierarchy, Section 5.2)
- `GPMTagsManager` becomes a thin wrapper that reads/writes via `GPMStorage`
- Migration function converts both old formats to unified schema
- Auto-tagger (4.1) must check tag count <= 5 before adding; shows warning toast if limit reached

### 1.4 XSS Fix — innerHTML Cleanup

Replace all direct `innerHTML` assignments with the existing `el()` helper or `document.createElement` + `textContent`. **All 6 innerHTML sites identified:**

1. `ui_elements.js` — `createModal()` body content injection
2. `ui_elements.js` — `showBackupPanel()` builds HTML strings with backup timestamps
3. `ui_elements.js` — `showTemplateDialog()` builds HTML strings with template names
4. `project-tree.js:1066` — Bulk toolbar builds HTML with `count` variable
5. `ui_elements.js` — Backup panel restore button area
6. `ui_elements.js` — Settings panel content generation

**Note:** `showBackupPanel` and `showTemplateDialog` require full DOM-construction rewrites (not simple find-replace) as they build large nested structures with user data. Use `el()` helper pattern exclusively.

## 2. Smart Organization

### 2.1 Chat Summary & Keyword Extraction

**New module:** `src/intelligence/chat-extractor.js`

**Flow:**
1. Trigger: When chat is added to a project, or weekly background scan
2. Extract: First user message + first 200 chars of last AI response
3. Keywords: Top 3-5 words by frequency (stop-words filtered, locale-aware)
4. Store: `chat.metadata = { summary, keywords[], extractedAt }`
5. Display: Hover tooltip on chat in project tree

**Approach:** Client-side regex + word frequency (no Gemini API call). Instant, works offline.

**DOM extraction strategy:** Uses existing `selectors.js` adaptive selector engine to find chat message elements. Extracts text from user prompt bubbles and AI response containers. If Gemini's DOM structure changes, `selectors.js` fallback discovery will locate message elements by structural heuristics. Extraction fails gracefully — if no content found, metadata stays empty (no error thrown).

### 2.2 Smart Project Suggestion

**New module:** `src/intelligence/project-suggester.js`

**Flow:**
1. Trigger: New chat detected (MutationObserver)
2. Compare:
   - Chat title vs project names (Levenshtein similarity)
   - Keywords of existing chats vs new chat keywords
   - Tag overlap
3. Score: 0-100, show suggestion if score >= 60%
4. UI: Suggestion chip **within GPM sidebar** (next to chat row in project tree): "Add to ProjectName"
5. Action: Single click to accept or dismiss

**Note:** Suggestions appear only inside the GPM sidebar, not in Gemini's native UI. This avoids fragile DOM injection into Gemini's chat list.

### 2.3 Auto-Categorization Rules Engine

**New module:** `src/intelligence/rules-engine.js`

**Rule structure:**
```js
{
  id: string,
  field: 'title' | 'content' | 'url' | 'keyword',
  operator: 'contains' | 'startsWith' | 'regex' | 'equals',
  value: string,
  targetProjectId: string,
  enabled: boolean,
  priority: number
}
```

**Flow:**
1. Rules evaluated in priority order when new chat detected
2. First matching rule assigns chat to target project
3. Multiple rules can coexist; highest priority wins

**UI:** Settings → "Auto Rules" tab with rule list, enable/disable toggles, add/edit/delete forms, "Run Now" button for existing chats.

**Storage:** `chrome.storage.local` → `rules[]`

### 2.4 Duplicate Chat Detection

**New module:** `src/intelligence/duplicate-detector.js`

**Flow:**
1. On chat add → compare with existing chats
2. Metrics: Title fuzzy match (%80+) + time proximity (within 24h)
3. UI: Warning banner: "This chat looks similar to [ChatName]. Merge or ignore?"
4. Action: Merge (redirect old reference to new) or Dismiss (save dismissal)

## 4. Automation & Workflows

### 4.1 Auto-Tagging

**New module:** `src/tags/auto-tagger.js`

**Rule structure:**
```js
{
  id: string,
  conditions: [{ field: 'title'|'content', operator: 'contains'|'regex'|'startsWith', value: string }],
  tags: string[],
  enabled: boolean,
  priority: number
}
```

**Flow:**
1. Rules evaluated when chat added to project (sorted by priority)
2. Matching rules append tags to chat (existing tags preserved)
3. "Run Now" applies rules to all existing chats

**UI:** Settings → "Auto Tags" tab.

**Integration:** Works alongside categorization rules (Section 2.3).

### 4.2 Scheduled Backup

**New module:** `src/backup/scheduled-backup.js`

**Mechanism:** Chrome Alarms API in `background.js`
- `chrome.alarms.create('gpm-backup', { periodInMinutes })` — daily (1440) / 3-day (4320) / weekly (10080)
- Service worker wakes up even when browser is idle
- **Manifest change required:** Add `"alarms"` to `permissions` in `manifest.json`

**Backup strategy:**
- **Incremental:** SW reads current storage, reads last backup, computes diff (added/removed project IDs and chat IDs). Stores `{ timestamp, type: 'incremental', added: [], removed: [] }`
- Full copy every 5th backup — stores complete data snapshot
- Rotation: Keep last 10, auto-delete older
- Each backup: `{ id, timestamp, type: 'full'|'incremental', size, data }`
- **Atomicity:** SW reads all data in one `chrome.storage.local.get()` call, writes backup in one `set()` call. If SW is killed mid-operation, the partial write is detected on next alarm (backup without valid `id` is cleaned up).

**UI:** Settings → "Backup" tab: frequency selector, backup history, one-click restore, "Backup Now" button.

**Notification:** Toast on backup completion (Section 3.4).

### 4.3 Enhanced Project Templates

Extends `src/templates/folder-templates.js`:

**Built-in templates:**
- "Software Project" → Design/Dev/Test/Docs folders + tags
- "Research" → Sources/Notes/Results + tags
- "Business" → Planning/Meetings/Tasks/Archive
- "Personal" → Journal/Goals/Notes

**New capabilities:**
- Folders + tags + kanban columns (Section 3.2 integration)

**UI:** Template selection dropdown in "New Project" dialog.

### 4.4 Bulk Operation Wizard

Extends `src/batch-operations.js`:

**Operations:**
- Bulk Move: To target project/folder
- Bulk Tag: Add/remove tags
- Bulk Rename: Add prefix/suffix, find/replace

**Selection methods:**

- "Select All" / "Invert Selection"

**UI:** Selection mode toggle → action toolbar → operation selection → confirm.

**Undo:** Every bulk operation is undoable (undo-redo stack, Section 5.5).

### 4.5 Pomodoro / Session Tracker

**New module:** `src/focus/session-tracker.js`

**Features:**

**UI:**

## 5. Existing Feature Improvements

### 5.1 Search Engine Upgrade

Extends search in `src/project-tree.js`:

**New capabilities:**
- Full-text search in cached chat content
- Regex support: `/pattern/` syntax with **ReDoS protection** — 100ms execution timeout via `performance.now()` check; invalid/unsafe regexes fall back to literal text search
- Combined filters: project + tag + date range (AND logic)
- Search history: Last 10 queries saved
- Highlight: Matching terms highlighted in results

**Performance:**
- Search index: `Map<keyword, chatId[]>` structure
- 300ms debounce on input
- Virtual list integration (Section 5.6) for large result sets

### 5.2 Tag System Upgrade

After schema unification (Section 1.3):

**New features:**
- Tag hierarchy via `parentId` field
- Tag colors: 10 presets + custom picker
- Type-ahead autocomplete when assigning tags
- Unused tag cleanup tool
- Per-tag usage statistics

**UI:** Tag manager panel, tree view in tag picker, color picker component.

**Migration:** Auto-converts old array format to new object format.

### 5.3 Sorting Improvements

Extends `src/sort-manager.js`:

**Multi-criteria sort:**
- Primary: Date / Name / Tag count / Last activity
- Secondary: Tiebreaker for same primary value
- Direction: Asc/Desc per criterion, independent

**Manual sort:**
- Drag & drop custom ordering
- `customOrder: [chatId, ...]` in project metadata
- Auto-sort disabled when manual sort active

**Grouping:**
- By tag (group headers above items)
- By project (in all-chats view)
- By date (Today / This Week / Older)

**UI:** Sort dropdown → add/remove criteria + drag-drop toggle.

### 5.4 Backup Improvements

Integrates with scheduled backup (Section 4.2):

**New features:**
- Version history with timestamp + size + change summary
- Incremental backups (delta only, ~10KB vs ~200KB full)
- Backup diff: Compare two backups, list additions/deletions
- Auto-cleanup: Keep last 10, delete 30+ day old incrementals
- Storage quota warning
- Export formats: JSON (existing) + ZIP (compressed)

### 5.5 Undo/Redo System

Extends existing `src/history/undo-redo.js` (which already has a working Command Pattern with `createAction()` and `MAX_HISTORY = 20`):

- Increase stack size from 20 to 50
- Add missing command types to existing `GPMHistory` system

**Architecture:** Command Pattern
```js
interface Command {
  execute(),
  undo(),
  describe()
}
```

**Supported operations (phase 1):**
- Chat move (between projects/folders)
- Tag add/remove
- Project/folder create/delete
- Bulk operations (single command)

**Stack:** In-memory, last 50 commands.

**UI:**
- Ctrl+Z / Ctrl+Y keyboard shortcuts
- Undo/redo buttons in sidebar header (disabled when stack empty)
- Post-undo toast: "Moved → Undo"

### 5.6 Virtual List

Replaces stub in `src/performance/virtual-list.js`:

**Approach:** Only render visible rows + 5-row buffer above/below.

**API** (aligns with existing `.setItems(items)` pattern):
```js
new VirtualList(container, items, renderItem)
  .setItems(newItems)         // existing method name
  .updateItems(newItems)      // alias, calls setItems
  .scrollToItem(index)
  .destroy()
```

**Config:** Fixed row height 48px, `requestAnimationFrame` throttled scroll.

**Integration:** Project tree chat list, search results (5.1), kanban cards (3.2).

**Target:** <16ms render with 10,000 items.

### 5.7 Analytics Implementation

Replaces stub in `src/analytics/usage-tracker.js`:

**Data collection:**
- Events: `project.create`, `chat.move`, `tag.add`, `search.execute`, `backup.create`
- Structure: `{ event, timestamp, metadata }`
- Retention: Last 90 days, older pruned

**Reports:**
- Daily/monthly activity summary
- Most active projects
- Most used tags
- Search query analysis (top search terms)
- Session durations (Section 4.5 integration)

**Role:** Data provider layer for Dashboard (Section 3.1).

**Privacy:** All data local, never transmitted (existing principle).

## Cross-Cutting Concerns

### Storage Budget

`chrome.storage.local` has a 10MB limit. Estimated storage usage:

| Data | Per Entry | Estimated Total (90 days) |
|------|-----------|--------------------------|
| analytics.dailyStats | ~500 bytes/day | ~45 KB |
| sessions[] | ~100 bytes/session | ~50 KB (5/day avg) |
| rules[] | ~200 bytes/rule | ~2 KB (10 rules) |
| templates[] | ~1 KB/template | ~10 KB |
| backups (10 versions) | ~200 KB full, ~10 KB incremental | ~600 KB avg |
| kanban state | ~50 bytes/project | ~5 KB (100 projects) |
| chat metadata | ~200 bytes/chat | ~200 KB (1000 chats) |
| search index | ~100 bytes/keyword | ~100 KB |
| **Total estimated** | | **~1.1 MB** |

This is well within 10MB. However, add `"unlimitedStorage"` permission to `manifest.json` as a safety net for power users with 5000+ chats.

### Schema Migration

All new storage keys require a schema version bump. Current storage uses no version key.

- Add `gpm_schemaVersion: 2` to `chrome.storage.local`
- On extension load (`content.js` init), check schema version
- Run migration functions for: tag schema unification, new analytics structure, kanban defaults
- Migration is idempotent — safe to run multiple times
- Backup created automatically before migration (existing backup-manager pattern)

### Internationalization

New modules will add ~200 new i18n strings across 17 locales:
- Dashboard labels and stat names
- Kanban default column names
- Template names and descriptions
- Rule engine condition labels
- Toast messages for new operations
- Session tracker labels
- Theme setting labels

Follow existing `t()` pattern from `src/i18n.js`. Add all keys to `_locales/en/messages.json` first, then propagate to other 16 locales.

### Error Boundaries

Intelligence modules (`src/intelligence/*`) are wrapped in try-catch:
- If `chat-extractor.js` throws → metadata stays empty, sidebar renders normally
- If `project-suggester.js` throws → no suggestions shown, no UI breakage
- If `rules-engine.js` throws → auto-categorization skipped, manual use unaffected
- Each module logs errors to `console.warn('[GPM] module-name:', error)` for debugging
- Error state stored per-module: `_moduleErrors: { chatExtractor: true }` — prevents retry spam

### Accessibility

- Board view drag-and-drop: Keyboard alternatives (arrow keys to move between columns, Enter to drop)
- Timeline view: Focus management, ARIA labels for date ranges and project rows
- Toast notifications: `role="alert"` + `aria-live="polite"` for screen readers
- All new modals: Focus trap, Escape to close, ARIA labels

### Multi-Tab Conflict Resolution

New storage keys need mutex protection similar to existing `_withLock`:
- Kanban state changes: Use existing mutex
- Rules/templates/theme: Read-heavy, write-rarely — use simple last-write-wins with debounce
- Analytics events: Append-only, no conflict
- Session data: Per-tab session IDs prevent conflicts
